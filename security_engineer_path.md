# Security Engineer Learning Path

## Goal
Move from SOC Analyst to Security Engineer with a focus on secure code review, threat modeling, and web application security.

## Step 1: Learn the fundamentals
- Study the OWASP Top 10 and modern web application vulnerabilities.
- Learn secure development concepts: authentication, authorization, session management, input validation, encryption, and error handling.
- Understand the software development lifecycle and where security fits in.

## Step 2: Hands-on labs
- Complete PortSwigger Web Security Academy labs.
- Use PentesterLab for real-world web app challenges.
- Avoid relying on outdated practice platforms; focus on current, industry-relevant content.

## Step 3: Secure code review
- Practice with Java first, since most code-review roles expect Java proficiency.
- Learn common Java vulnerabilities and secure coding patterns.
- Supplement with Python, Node.js, and Go when needed.

## Step 4: Practical threat modeling
- Start with simple architectures and identify assets, threats, and mitigations.
- Use templates like STRIDE or attacker scenarios.
- Apply threat modeling to the applications and APIs you review.

## Step 5: Build practical skills
- Do Capture The Flag (CTF) challenges regularly, especially on weekends.
- Solve problems manually first, then use tools to verify.
- Build small scripts in Python or shell for automation, scanning, and analysis.

## Recommended resources
- PortSwigger Web Security Academy
- PentesterLab
- OWASP WebGoat or Juice Shop for practical learning
- Capture The Flag platforms like Hack The Box, TryHackMe, or CTFtime

## Notes
- Keep a log of what you learn and the vulnerabilities you practice.
- Focus first on understanding the vulnerability, not just exploiting it.
- This branch is `security-engineer-path`.
